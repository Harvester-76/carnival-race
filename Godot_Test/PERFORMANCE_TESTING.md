# Stage 2.3: performance test guide

## In-game controls

- **F3** toggles the performance overlay.
- **F4** starts a new CSV recording; pressing F4 again closes that file. Pressing it once more starts another uniquely named recording.
- **Esc** opens the pause menu. The technical engine screen is now on **F6**; gamepad menu controls are unchanged.

The CSV and a JSON metadata file are written to `user://performance_logs/`. On macOS, Godot resolves this below `~/Library/Application Support/Godot/app_userdata/Карнавальская Гонка/performance_logs/`. Godot prints both absolute paths when recording starts and prints the CSV path again when recording stops. Files are timestamped and are never overwritten.

## Metrics and portability

The overlay shows current FPS, 10-second average FPS, 1% low, current frame time, P95/P99 frame time, physics frame time, draw calls, render objects, collision counts, Godot static memory, resource count, startup timings, ship position/speed, and the Static physics-ray height difference from analytic `height()`. The last value is `N/A` for Generated, before the first valid ray hit, or when Static has no physics hit.

Frame samples are kept in a fixed-size ring buffer. Percentiles use the last 10 seconds of frame-time samples. **1% low FPS** is calculated as FPS for the mean frame time of the slowest 1% of those samples; it is not the minimum FPS seen.

Godot's portable monitors expose its static-memory counter and resource count, but do not expose a portable macOS/Windows process working set or resource-byte total. These CSV columns are left blank and the overlay shows `N/A`. Video memory is shown only when Godot's monitor returns a positive value; otherwise it is blank/`N/A`.

CSV samples are recorded at 2 Hz. Event rows use the same columns and set `record_type=event`; `event` identifies load starts/completions, chunk load starts/completions, delays/missing files, and recording start/stop. `physics_analytic_delta_m` is blank when unavailable. Startup timing is included in metadata and repeated in initial event rows because the user cannot start a recording while the loading screen is active.

## Repeatable Generated / Static comparison

Use the same executable, machine, display resolution, project graphics settings, ship, difficulty, camera, scheme, seed, length, and `ab_slot` for both runs. `ab_slot` is zero-based in the original row-major start grid; it fixes the player's position and keeps bot slots in the same deterministic order. Without `ab_slot`, normal play keeps its existing randomized lineup.

Example commands from the project directory:

```sh
Godot --path . -- track_source=Generated track=11 len=650 ab_slot=0 ship=0 level=0 cam=0 scheme=0 no_flight_log
Godot --path . -- track_source=Static track=11 len=650 ab_slot=0 ship=0 level=0 cam=0 scheme=0 no_flight_log
```

For each run:

1. Wait for the loading screen and start countdown to finish. Startup/load durations are reported separately from gameplay samples.
2. Start CSV recording with F4.
3. Fly the same route and use the same controls for the same duration. Avoid changing the camera, pausing, or opening menus during the measured segment.
4. Stop recording with F4 and keep the matching JSON metadata file.
5. Repeat in the other mode with the same arguments and test sequence.

Generated remains the default when no saved mode or `track_source` argument selects Static. No automatic ship control is used.

## Separate full export

The game never starts the exporter. Run `bash tools/export_static_track.sh` on macOS or `powershell -ExecutionPolicy Bypass -File .\tools\export_static_track.ps1` on Windows. Set `GODOT_BIN` on macOS or `GODOT_EXE` on Windows if Godot is not on PATH. Both scripts refuse an existing output directory. To export elsewhere, set `STATIC_TRACK_OUT` to a new path.

Run the validator separately after a successful export:

```sh
python3 static_track_pipeline/validate_static_track_fixture.py experiments/full_static_track_seed11_650km
```

The currently present full export is not regenerated by this guide or by ordinary game startup.

## Known findings and test scope

During Stage 2.2 on macOS, the previously observed terrain hole after the second cut was not visible. This is a macOS observation only, not proof that the geometry or Windows runtime is universally hole-free. Windows testing still requires a Windows machine.

The prior Static runtime ray diagnostic returned `N/A` for a physical ray hit during the observed run; the analytic clearance was available, but physical-versus-analytic height comparison could not be measured in that run. The performance CSV reports the engine monitors and collision streaming counters independently.
